与 AI 协作全过程记录 —— 「大学生健身台」从 idea 到上线

作者：李海铨 项目：大学生健身台（课表 × 训练计划轮换 × 身体数据） 在线地址：https://fitness-dashboard-orcin-alpha.vercel.app/ 代码仓库：https://github.com/877305755-cell/fitness-dashboard 记录时间：2026-09-17 ~ 2026-09-20

本文档整理了我与 AI 助手（WorkBuddy）协作完成这个网页的完整对话过程，包括每一步做了什么、遇到过哪些报错、以及怎么解决的。

第一阶段：需求对话（9 月 17 日晚）

我对 AI 说：发了几张别人做的健身工作台截图，说"帮我做个类似的健身工作台，但是我是一名大学生我有课，我想把课表也放上去来合理安排我的时间"。

AI 做了什么： - 先跟我确认方案：原版有 4 个模块，加课表就 5 个，超出单次搭建上限，提出分期方案（本期做 4 个核心模块，饮食建议放二期） - 问我选什么配色，我选了黑底 + 深暗红 - 确认数据表结构（14 个字段）后开始搭建

产出：第一版上线，包含今日待办、今日课程+空闲时段、课表、训练打卡、身体数据 5 个模块。

第二阶段：需求迭代（9 月 17 日深夜 ~ 18 日）

我对 AI 说的三句话，每句都让页面进化一次：

  1. "我想把训练和课表合成一个类似日历的东西……我想他可以让我先选择训练计划如三分化五分化之类的，再安排训练的部位，训练的部位里再有选择添加的训练动作" → AI 把课表+训练合并成月历视图，新增「计划」页：选分化模板 → 排部位 → 填动作 → 自动铺满两个月日历

  2. "我的计划不能生成和保存" → AI 排查出根因：数据表的「分类」字段没有「计划」这个选项，页面写入被服务端拒绝。给字段补上选项后端到端验证通过。我学到了：页面上新增的每个选项，数据库字段也要同步支持。

  3. "三分化指的是练三天然后休息一天，然后接着练三休一，一直循环下去，别的 n 分化也是一样" → AI 把轮换逻辑改成「练 N 休 1」：三分化 = 胸 → 背+二头 → 肩 → 休 → 循环。日历上自动出现灰色的"休"。

  4. "添加课程的地方多添加一个单双周选项，因为有些课程是第一周有第二周没有" → AI 加了单双周字段，按自然周奇偶（单周/双周）自动过滤课程；顺手修了全角冒号时间（"08：40"）识别不了的问题。

  5. "我添加错课程 我想删除" / "把日历做大点" / "课程名称首字、开始时间、地点也显示在日历上" / "加一个计算 BMI" → AI 加了课程管理列表（一键删除）、放大日历格子、格子里直接显示课程信息、按我给的公式做了 BMI + 体脂率计算器。

第三阶段：部署闯关（9 月 18 日，AI 当教练）

这一阶段 AI 没有替我操作，而是像教练一样给我地图和命令，每一步都是我自己在终端里敲的。

第 1 关：传到 GitHub

AI 先探明我电脑的环境（git 已装、身份已配好），然后给我四步地图：

init   → 让 git 开始盯着这个文件夹
add    → 把要传的文件勾进清单
commit → 存一档
push   → 上传到 GitHub

我自己跑了：

git init
git add fitness-dashboard.html
git commit -m "feat: 大学生健身台"
git remote add origin https://github.com/877305755-cell/fitness-dashboard.git
git branch -M main
git push -u origin main

push 时浏览器弹出 GitHub 授权页面，登录后自动继续，看到 [new branch] main -> main 通关。

第 2 关：Vercel 部署

AI 提前预警了一个坑：纯静态网页必须有一个叫 index.html 的文件当入口，否则打开网址会 404。于是我补了一个文件再推送：

Copy-Item fitness-dashboard.html index.html
git add index.html
git commit -m "add index.html for Vercel"
git push

然后去 vercel.com 用 GitHub 账号登录 → Import 仓库 → 点 Deploy，十几秒后拿到网址。

第 3 关：第 3 次 commit（README）

在 GitHub 网页上直接创建了 README.md（项目说明书）。

意外遭遇：第一次真正的 git 冲突

因为 README 是在网页端建的（存在云端），我本地电脑不知道这件事，git pull 时报错：

error: The following untracked working tree files would be overwritten by merge:
README.md
Please move or remove them before you merge.

AI 教我读报错：untracked = 本地有个 git 没纳管的文件，move or remove = 让我挪走或删掉。我按提示先备份再删除，重新 pull，看到 Fast-forward 成功同步。

这次报错让我印象最深：git 不是坏了，它在保护我——没存过档的文件一旦被覆盖就找不回来，所以它宁可停下来问。

第四阶段：持续迭代（9 月 19 日）

  • 给页面底部加署名，自己走了一遍完整流程：改文件 → git add → git commit → git push → Vercel 自动重新部署
  • 到今天仓库已经有 5 次提交记录，每次都能在 GitHub 的 commits 页面回溯

我学到的

  1. 和 AI 协作的正确姿势：把需求说具体（"三分化是练三休一"比"优化一下"有用一百倍）；报错整段贴给 AI，别只说"不行了"
  2. AI 也会记错：Vercel 界面改版后按钮名字变了，我照 AI 说的找不到，反馈后 AI 承认是它记的旧版本——AI 说的按钮界面上没有时，要大胆说出来
  3. Git 的心智模型：commit 是本地存档，push 是同步云端，pull 是把云端拉回本地；git 绝不擅自覆盖你没存过档的东西
  4. 部署不是玄学：静态网站 = 文件放到 24 小时开机的服务器；入口文件必须叫 index.html；push 之后托管平台自动更新
